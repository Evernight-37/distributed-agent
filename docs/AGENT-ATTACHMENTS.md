# Agent 回复附件（2.1.2 开发版）

在群聊或与 Agent 的私聊中，直接说“把这份报告 PDF 作为附件发给我”，必要时指出它在项目中的位置。Agent 会把文件附在同一会话的最终回复中，点击“下载”即可保存到自己的电脑，不再只是给出服务器本地路径。

托管端和执行 Agent 的接收端都需要更新。原有桌面附件下载界面可以继续使用。每条回复最多 5 个文件，每个最大 5 MB；项目附件试用总量仍为 512 MB。大文件请使用独立文件速传；本次改动不增加 Linux 主动发送大文件的 CLI。

接收端只读取已经登记的项目目录内的普通文件，拒绝隐藏路径、设备和目录。Agent 可以决定发送与当前对话相关的项目文件，但不得发送凭据。机器所有者在员工设置中决定附件权限：

- **请求批准**（默认）：每次发送前，账户所有者在任意已登录机器的控制台审阅文件名和大小，再批准或拒绝。
- **帮我批准**：当前会话中人类明确要求发送相同文件时自动放行；其他情况请求所有者批准。这是确定性的保守规则，并非另一个模型审核。
- **完全访问权限**：项目目录内符合文件安全检查和大小限制的文件自动发送。此项不扩大 Codex CLI 的文件或执行权限。

批准请求保存在协作服务中，不要求所有者与 Agent 使用同一台机器。批准后，接收端会重新读取并核对文件名、大小和 SHA-256；文件变动时停止发送。等待批准期间该任务保持活动，批准或拒绝后再上报最终回复。

## 平台与信任范围

Mac/Linux 接收端使用逐级目录文件描述符和 `O_NOFOLLOW` 读取。Windows 接收端先打开文件句柄，再核对句柄的实际路径和文件属性，防止目录链接或替换把读取转向项目外。Windows 手动上传和下载附件继续可用。

模型可能误判文件相关性。使用“帮我批准”或“完全访问权限”时，不需要分享的敏感文件应放在项目目录外；尤其“完全访问权限”不进行逐件人工确认。项目目录限制、文件类型、大小、任务租约和会话权限仍由代码验证。

## 执行端协议

Agent 的结构化回复增加 `attachments: [{"path": "reports/result.pdf"}]` 字段，不发送文件时返回空数组。相对路径以该员工的项目目录为基准；现有完整项目内路径也可使用。模型不会获得设备令牌、账户私钥或上传票据。

需要批准时，接收端先用 `/api/device/task-attachment-request` 向协作服务登记文件清单和哈希。账户所有者在桌面端审阅；决定通过设备轮询返回。放行后，接收端用当前设备凭据、作业 ID、租约和 0～4 的附件槽位，调用 `/api/device/task-attachment`，提交文件名与 Base64 内容。单次请求最多 8 MB，文件本身仍限 5 MB。其他设备接口仍保持原来的请求大小限制。

托管端验证设备、租约、Agent、项目成员和任务状态。槽位生成固定附件 ID：同一槽位、同一文件的重试不会重复上传，也不能覆写内容。任务结束后只允许确认已有同内容上传，不能追加文件。

接收端在上报最终报告前删除附件路径，仅回传上传得到的 ID。调度器只接受属于当前作业的附件，绑定到最终回复；下载继承该消息的群聊或私聊权限。上传中断会重试，路径、大小或权限错误会在回复中显示发送提示。旧托管端会得到明确升级提示，不会把本地路径伪装成已经发送的附件。
