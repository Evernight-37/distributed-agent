# 账户、员工与项目：下一版应用设计

状态：已确认信息结构；`web/design.html` 是可点击设计稿，全部为示例数据，不接入生产账户。现有 Windows 应用、服务及数据仍保持可用。本文描述的是目标行为，不代表这些后端能力已经实现。

## 页面结构

| 页面 | 用户要做的事 | 默认信息 | 深入操作 |
|---|---|---|---|
| 注册 / 登录 | 创建或解锁自己的本地账户 | 名称、账户选择、密码 | 加入已有账户设备、账户恢复 |
| 控制台 | 看自己的员工和项目 | 全部自己的 agents 的名称、模型、机器、状态；项目名与上次进入对话时间 | 添加 agent、展开单个 agent 设置、新建项目、加入邀请 |
| 项目 | 讨论、派遣员工、查看进度 | 群消息、成员、已派遣 agents | 群主选择管理员和邀请人；成员派遣、撤回自己员工；展开私聊审计与任务 |
| 设置 | 管理账户和本机 | 账户、我的设备、本机偏好 | 存储与备份、外观、通知、折叠的高级连接诊断 |

技术连接信息不占据首页。设置模型是员工的操作；设置管理员是项目的操作；作业批准留在对应项目任务详情中，并标明执行机器。

## 账户与设备

同一个人的多台电脑共享账户，可以在任意已授权设备上看到自己全部员工、项目、消息和任务。默认员工筛选是“全部机器”，另有“本机”筛选。

账户资料及设备私密身份保存在各自电脑。协作服务保存参与协作所需的公共身份、设备授权、成员关系和共享元数据，不保存本地解锁密码。Codex 凭据不随账户复制，每台电脑使用自己的 Codex 登录。

身份设计使用独立设备密钥及账户授权记录：新电脑请求加入，已有可信设备由本人批准，协作服务登记新的设备公钥与账户关系。不在电脑之间复制私钥，也不把显示名当身份标识。不自行实现密码学；实现时选用经过验证的签名和加密组件、操作系统密钥存储。

注册个人账户、授权设备、加入项目是三个独立概念。新成员不应为了创建自己的本地账户先获得某个项目邀请。邀请只决定项目成员权限。

已有设备遗失后，在仍能使用的可信设备上撤销它；恢复渠道需要独立的用户备份。密码找回不能由普通项目群主决定。产品不得宣称服务运营者看不到现有未加密的项目消息。

## 员工与派遣

员工是持久身份，归属于账户和具体机器。在控制台创建和配置，不必先加入项目。项目中的派遣记录与执行会话独立于员工身份。

一位员工可以参与不同项目，但每个项目使用独立执行会话、消息范围和工作目录绑定。不能把已有会话在项目之间直接复用，也不能把私聊历史传给其他项目。

本机配置拥有最终执行检查：请求来自同一账户的另一台授权设备时，也必须检查本机注册目录、阶段、模板和任务状态。其他人、项目管理员 agent 或协作服务不能使用这种通道改变机器权限。

在另一台自己的设备上修改 agent 的模型或授权时，界面分别显示“请求修改”“设备已应用”的版本；离线时显示“等待设备上线”，不得提前当作生效配置。任务启动时冻结所用版本，运行中不自动切换模型。不自动推断、替换已注册的模型或思考强度。

允许讨论、检查与修改分开设置。修改工作区仍要求专属 linked Git worktree。后台执行保持独立进程；关闭窗口不取消已启动任务。暂停、停止接收、撤回员工与取消具体作业须分别说明影响。

## 共享范围

| 信息 | 跨自己的设备可见 | 自动复制文件 |
|---|---|---|
| 账户资料、设备列表、员工配置与状态 | 是 | 不复制 Codex 登录或设备私钥 |
| 项目成员、群消息、任务与结果索引 | 是 | 无 |
| 上次进入项目对话的时间 | 是，按该账户最近一次进入记录 | 无 |
| 项目目录、环境、训练数据、模型权重 | 可显示对应机器与路径说明 | 否 |
| 实验结果或代码 | 按项目约定分享 | 仅在明确任务中传输或通过 Git 协作 |

不默认同步项目文件，这是分布式分工的基本边界。界面明确显示结果所在机器，避免把远端路径误当本机可打开的目录。

## 项目权限

- 群主：命名项目、邀请人类成员、选择管理员 agent、控制项目状态。
- 人类成员：查看项目群聊和私聊审计，派遣、设置和撤回自己的员工。
- 管理员 agent：协调讨论、分工、发项目内消息和任务，不能变更人类身份或设备所有权。
- 普通 agent：只接收本项目群消息、自己的私聊与任务。
- 服务运营者：负责消息服务可达和备份，不获得产品内的成员机器控制权限；其对数据库的访问能力需诚实说明。

## 现有实现的改造点

1. 当前 `Store.users` 保存服务端密码验证数据。本地身份登录需新增认证协议并支持旧账户显式迁移；不能只把登录表单改名为“本地”。
2. 当前 agents 表和本机绑定以项目执行会话为中心。需增加账户级员工目录、项目派遣表和独立执行会话标识，再迁移已有 agent ID 与会话。
3. 当前设备轮询只上报绑定，不接收远端模型配置。跨自己设备的配置须新增主人授权与设备确认通道，不能借用普通任务队列绕过本机边界。
4. 当前项目快照没有“上次进入”字段。新增成员级访问记录，只在主动进入对话时更新，后台刷新不算进入。
5. Windows 应用应在同一窗口呈现控制台与项目，不再让用户来回操作启动器和浏览器。连接诊断和托管服务选项放到高级设置。

## 实施与验收

先评审交互稿，再接入本地登录、旧身份迁移、账户级员工目录、跨设备授权和项目派遣。按可验证的完整流程交付，不把仅绘制的按钮描述成已实现功能。

关键验收：两台电脑授权为同一账户后看到相同员工和项目；其他账户不能控制这些员工；离线配置显示待应用；目录与 Codex 凭据没有被复制；派遣到不同项目不泄露会话；旧数据可继续使用且有回滚；任何新登录或邀请不能启动模型任务。
