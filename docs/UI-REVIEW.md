# Foolship 桌面界面调研与改版

后续界面改动沿用 [Foolship 桌面界面指南](UI-STYLE.md)。

## 同类产品观察

| 产品 | 界面组织 | 对 Foolship 的启发 |
| --- | --- | --- |
| Cursor | Agent 在面板里接收指令，修改可沿着 diff 审阅。 | 聊天里呈现任务事件，任务卡里的详情和审阅入口放在一起。 [Agent mode](https://cursor.com/help/ai-features/agent) |
| VS Code Copilot | Agents 窗口将会话列表、当前会话、文件与变更检查分到不同区域。审阅控件靠近对应变更。 | 会话切换、聊天、任务检查各有明确位置。审批应显示对象和范围，动作紧挨状态。 [Agents window](https://code.visualstudio.com/docs/agents/run/agents-window) · [Review code edits](https://code.visualstudio.com/docs/agents/run/review-code-edits) |
| Claude Code Desktop | 对话旁放可按需开启的会话详情，展示执行环境、变更和进度。空间不足时可切换面板。 | 大窗口常驻任务和成员，小窗口可直接跳到它们，同时给消息和输入保留空间。 [Desktop application](https://code.claude.com/docs/en/desktop#arrange-your-workspace) |
| Codex 桌面 | 用项目组织独立线程，线程中能审查执行结果。 | 首页先让用户找到项目以及待处理的审批，进入项目后再集中显示消息和交付。 [Introducing the Codex app](https://openai.com/index/introducing-the-codex-app/) |
| Windsurf Cascade | 在会话中安排待办、工具调用和检查点。 | 将工作进度和任务结果向用户呈现为可辨认的状态，详细记录按需展开。 [Cascade](https://docs.devin.ai/desktop/cascade) |

共同点是把高频操作留在固定位置，把详情放在与对象相邻的区域。Foolship 需要让用户区分聊天、正式草稿、待审批和已经交付的结果，因此任务状态使用文字标注，颜色辅助识别。

## 界面审查与落地

| 位置 | 原有问题 | 这轮处理 |
| --- | --- | --- |
| 主导航 | 小图标含义需要猜，选中状态和账户位置不够明显。 | 保留常驻导航宽度，加可见文字和明确选中状态。窄窗口把导航移到顶部。 |
| 控制台 | 新建和加入项目不在一起，待处理入口位置偏后。 | 新建是主操作，加入紧邻其旁。待审批有记录时出现在项目列表前。 |
| 会话列表和聊天 | 会话列表占宽，聊天要滚到下方找任务。发送主要靠占位文字提示键盘操作。 | 大窗口显示会话、聊天、任务检查三栏。窄窗口保留任务入口，进一步变窄时将会话压成横向列表。输入区保留发送目标，并提供可见的发送和附件入口。 |
| 聊天排版与任务卡 | 人名、时间、状态都挤在正文附近，各类卡片层级接近。 | 人名和时间形成稳定的消息头，正文行距加宽。任务标题、状态和结果分层，草稿用琥珀提示，交付和验收使用绿系标记。 |
| 设置、账户和文件 | 设置项平铺，说明和按钮容易混成一组。相同性质的状态和操作排布不一致。 | 设置按服务与接收、模型与运行、协作接入、维护分组。设备和文件使用状态行。诊断、重命名和查看等次要动作使用更低的视觉权重。 |
| 登录与弹窗 | 小号浅色说明较多，复选项易错位，打开和关闭弹窗时键盘位置不稳定。 | 登录主操作和账户选择更集中，复选框整行可点。对话框滚动区与动作区分开，支持键盘循环、退出和焦点恢复。 |

正文基准为 14 像素，次要信息多为 12–13 像素，页面标题为 22–26 像素。暖灰背景和薄边框区分结构，深绿标记主操作与选中态，风险和待处理状态配有明确文字。说明文字保留会影响决策的内容，包括权限范围、连接失败和操作后果。

## 验证

- 使用 Edge 和示例数据检查 1220、1000、800 和 390 像素宽度的项目页。核对输入框初始可见、会话选中状态和横向溢出。
- 模拟项目消息发送、审阅并确认指定草稿版本、设置分组定位、打开账户与文件页面，以及通过复选框文字切换自动登录。
- 核对弹窗首次聚焦、Escape 关闭和焦点回到原按钮。执行前端测试及会话隔离、任务卡、事件和版本打包相关的 Python 测试。
