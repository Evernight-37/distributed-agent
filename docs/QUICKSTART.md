# Agent Harness 新手教程

这份教程面向第一次使用组网和 Agent 协作的人。除安装 Tailscale、安装 Agent Harness 和登录 Codex 外，后续操作都在应用按钮中完成，不需要打开终端。

## 先认识三个东西

| 工具              | 作用                                          | 它不负责什么                                      |
| ----------------- | --------------------------------------------- | ------------------------------------------------- |
| **Tailscale**     | 让分处不同网络的电脑能够安全互相访问          | 不保存 Harness 账户、项目或聊天                   |
| **Agent Harness** | 管理身份、设备、项目、消息、Agent 和任务路由  | 不代替 Codex 生成答案，也不自动安装 Tailscale     |
| **Codex CLI**     | 在每台 Agent 所在电脑上实际运行模型和完成任务 | 不自动加入 Harness 项目；需要在那台电脑上单独登录 |

只有一台电脑、只给自己使用时，不需要 Tailscale。创建账户、添加本机 Agent、创建本机项目即可。

多人协作时，先完成 Tailscale，再配置 Harness。不要把 Tailscale 的 `100.x.x.x` 机器地址当作 Harness 团队服务地址；Harness 最终要分享的是形如 `https://电脑名.xxxx.ts.net` 的 HTTPS 地址。

## 多人协作前准备

请先确认：

- 群主和每位同事都已安装 Agent Harness。
- 群主准备一台保持在线的电脑托管项目协作服务。它保存项目成员、消息和任务记录。
- 群主和同事都已安装 Tailscale，并且各自使用受邀的身份登录。
- 每台准备运行 Agent 的电脑都已安装 Codex CLI，并在该电脑上完成 Codex 登录。
- 每个人创建自己的 Harness 账户。不要共享 Harness 账户、解锁密码或设备关联码。

本文把创建项目和邀请成员的人称为**群主**，把运行团队入口、保存项目数据的电脑所有者称为**服务托管者**。常见情况下两者是同一个人。

## 第 1 步：群主先邀请同事加入 Tailscale 网络

### 群主操作

1. 打开 Tailscale 管理台。
2. 进入 **Users → Invite external users**。
3. 输入同事使用的邮箱并发送邀请。
4. 同事接受后，在 **Users** 中确认该用户已加入；在 **Machines** 中确认双方电脑在线。

### 同事操作

1. 打开邀请邮件或邀请链接，使用**收到邀请的那个身份**接受。
2. 打开电脑上的 Tailscale，使用相同身份登录。
3. 在 Tailscale 客户端或管理台确认自己的设备为在线状态。

**看到什么算成功：** 群主能在 Tailscale 的 **Machines** 中看到同事电脑，同事也已登录受邀的网络。显示的 `100.x.x.x` 是机器地址，只用于判断组网是否成功，后面加入项目时不要填写它。

如果看不到同事的 machine，先检查同事是否使用了受邀的身份、邀请是否已接受、Tailscale 是否显示已连接，以及群主是否在正确的 Tailscale 网络中。不要继续创建项目入口，先把这一步处理好。

## 第 2 步：每个人创建自己的 Harness 账户

群主和同事分别在自己的电脑打开 Agent Harness：

1. 点击 **创建账户**。
2. 填写自己的账户名称和本机解锁密码。
3. 展开的“连接设置”保持默认即可；点击 **创建并进入**。

**看到什么算成功：** 进入控制台，左下角显示自己的账户，控制台能看到“我的 Agents”和“我的项目”。

Harness 账户属于个人。加入别人的项目不需要重新注册，也不应该登录群主的账户。设备关联码只用于同一个人的第二台电脑，不能用来邀请同事。

## 第 3 步：群主创建团队服务地址

在准备长期在线的托管电脑上：

1. 打开 **设置 → 协作服务**。
2. 点击 **创建团队入口**。
3. 如果显示“等待 Tailscale 确认授权”，点击 **打开 Tailscale 授权页面**，在浏览器中允许 Serve。
4. 回到 Harness，等待状态变为“团队入口已就绪”。
5. 点击 **检测连接**。
6. 检测通过后点击 **复制地址**。

**看到什么算成功：** 页面显示“团队入口已就绪”，连接检测通过，并出现形如 `https://电脑名.xxxx.ts.net` 的“团队服务地址”。这才是之后要发给同事的地址。

Harness 只通过按钮配置入口，不会自动安装 Tailscale，也不会代替用户登录 Tailscale。托管电脑、Tailscale 和 Harness 服务需要保持运行；普通 Wi-Fi 改变不影响这个 `ts.net` 地址的用途。

## 第 4 步：群主创建项目并生成项目邀请码

1. 回到 **控制台**，点击 **＋ 新建项目**。
2. 填写项目名称，在“项目所在的协作服务”选择自己的托管电脑。
3. 点击 **创建并进入**。
4. 在项目的成员区域点击 **邀请成员 → 生成邀请**。
5. 把以下两项同时发给同事：
   - 第 3 步复制的 HTTPS 团队服务地址；
   - 本项目生成的“项目邀请代码”。

**看到什么算成功：** 群主进入新项目，并能看到项目邀请代码与协作服务地址。

项目邀请码授予项目成员权限；它和第二台电脑的设备关联码完全不同。不要把自己的设备关联码发给同事。

## 第 5 步：同事加入项目

同事保持登录自己的 Harness 账户：

1. 在控制台点击 **凭邀请加入项目**。
2. “协作服务地址”粘贴群主发来的 `https://...ts.net` 地址。
3. “项目邀请代码”粘贴群主发来的项目邀请码。
4. 点击 **加入**。

**看到什么算成功：** 应用提示已加入相应服务上的项目，项目出现在“我的项目”列表中。群主打开项目后也能看到该成员。

## 第 6 步：同事接入本机 Agent

同事如果希望自己的电脑为这个项目执行任务，还需要单独接入：

1. 打开 **设置 → 已加入的协作服务**。
2. 在群主的服务旁点击 **接入本机 agent → 确认接入**。
3. 在 **设置 → 本机接收任务** 点击 **启动接收**。
4. 回到 **控制台 → 我的 Agents → ＋ 添加员工**。
5. 选择自己的机器，填写员工名称，然后在“设置”中确认项目目录、Codex CLI、模型、思考强度和权限。
6. 打开项目，点击 **派遣我的员工**，选择刚创建的 Agent。

群主也按相同步骤添加和派遣自己的 Agent，并在项目中选择“管理员 Agent”。

**看到什么算成功：** “已加入的协作服务”显示“本机已接入”，本机接收服务已启动，Agent 显示已启用并出现在项目成员中。发送普通群聊后，管理员 Agent 能回复；要指定非管理员 Agent，请使用发送区的“呼叫 Agent”选择它。

Codex CLI 必须在 Agent 所在的那台 Windows 电脑上已经登录。Harness 不会替用户安装 Codex，也不会替用户完成 Codex 登录。

## 同一个人的第二台电脑

这一流程仅适用于同一个人共享同一 Harness 账户，与邀请同事无关。

| 新电脑                                                                     | 已登录的电脑                                                |
| -------------------------------------------------------------------------- | ----------------------------------------------------------- |
| 登录页点击 **关联我的另一台电脑**                                          | 点击左下角账户图标，进入 **身份与关联设备**                 |
| 填写已有账户使用的可达 HTTPS 服务地址和机器名称，点击 **获取新电脑关联码** | 点击 **输入新电脑的关联码**，输入关联码并核对设备名称和指纹 |
| 等待批准                                                                   | 点击 **核对请求 → 核对并批准 → 批准关联**                   |
| 点击 **检查批准并完成关联**                                                | 两台电脑均出现在自己的设备列表中                            |

设备关联码大约 10 分钟有效，只用于一次设备关联。项目邀请码用于邀请其他人进入某个项目，两者不能混用。关联后账户、Agent 配置和项目列表可见，但项目文件、Codex 登录和设备私钥不会自动同步。

## 常见问题

### Tailscale 看不到同事的 machine

确认群主使用 **Users → Invite external users** 邀请；同事必须用受邀身份接受并登录。双方设备都应在 Tailscale 客户端中显示已连接，并在管理台 **Machines** 中在线。若没有 machine，Harness 也无法跨网络连接。

### 出现 `WinError 10061` 或“目标计算机积极拒绝”

这通常表示地址能找到，但服务没有接收连接。检查托管电脑是否在线、Harness 是否仍在运行、团队入口是否显示“团队入口已就绪”，再点击 **检测连接**。不要把超时时间调大来掩盖连接问题。

### 地址里出现 `127.0.0.1`

`127.0.0.1` 永远只代表“当前这台电脑”。单机使用可以用；发给同事一定无效。请由服务托管者在 **设置 → 协作服务** 创建入口，并分享应用显示的 `https://...ts.net` 地址。

### 团队服务页面打不开

逐项检查：同事 Tailscale 是否已连接受邀网络；托管电脑是否在线；Serve 是否已在授权页面允许；地址是否完整包含 `https://`；Harness 的 **检测连接** 是否通过。`100.x.x.x` 机器地址不能代替团队服务地址。

### Agent 不回复

依次确认：

1. Agent 所在电脑的 Codex CLI 已登录；
2. **已加入的协作服务**显示本机已接入；
3. **本机接收任务**已经点击“启动接收”；
4. Agent 已启用并派遣到当前项目；
5. 普通群聊有管理员 Agent，或发送时通过“呼叫 Agent”选中了目标；
6. 代理设置与这台电脑的网络环境相符。

Agent 读完消息后可以选择不发言；但任务出现 `failed`、`interrupted` 或长时间“正在回复”时，应打开任务状态查看实际错误。

## 在 Codex 客户端中使用协作

需要时可打开 **设置 → 在 Codex 中使用协作**，点击“连接到 Codex”。连接后，普通 Codex 对话可以在用户授权范围内读取 Harness 项目、发送消息和给自己的 Agent 派发异步任务。该连接不能邀请成员、控制别人的机器或批准执行命令。
