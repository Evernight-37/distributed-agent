# 第一次使用：全程按钮操作

Windows 应用包解压后，双击 **AgentHarness.exe**。请保留整个应用文件夹；不需要安装 Python、配置 PATH 或运行终端命令。

## ① 打开或创建工作台

- 自己建工作群：点 **创建 / 打开我的工作台**，浏览器会打开工作台。
- 加入伙伴的工作群：填写团队提供的服务地址，点 **打开团队工作台**。

首次创建自己的工作台账户；已有账户直接登录。新成员用群主给的项目邀请代码 **凭邀请注册**。工作台用户名和密码与 OpenAI/GitHub 独立，密码没有长度限制，可以留空。

每台机器仍需要已有可用的 Codex 登录。应用不会替你登录 OpenAI，也不会上传它的认证文件。

## ② 创建项目，生成机器配对码

在工作台点 **＋ 新建**，填写项目名。进入 **成员与设置 → 配对我的机器**，填写这台机器的名称，复制配对码。

“生成邀请”的代码是给人加入项目的；“配对我的机器”的代码是给自己的电脑，两种代码不能混用。

## ③ 在目标电脑连接

在这台电脑的 Agent Harness 应用填写服务地址和机器配对码，点 **配对并启动**。配对码十分钟有效，只能使用一次。

配对成功后，会保留身份，按钮变为 **启动接收**；以后不用重新配对。连接不等于授权执行，agent 仍需要下一步启用。

## ④ 用文件夹选择器配置 agent

1. 填一个本机项目名（英文或数字），点 **选择项目文件夹…**。
2. 选择 **共享项目**，填写模型和选择思考强度。
3. 勾选 **启用本项目的 Agent**。第一次可只允许“讨论”。
4. 点 **保存本机项目设置**。

共享项目列表为空时，先在工作台创建或加入项目，等几秒再点 **刷新状态**。每台机器的主人独立控制它的模型、目录和权限。

允许修改文件时，需要专属 linked Git worktree。“高级设置 / 作业批准”用来登记固定命令模板、批准后台作业，以及查看已有绑定。

## ⑤ 开始群聊

回工作台，在 **成员与设置 → 设置管理员** 中选一个 agent。进入群聊发送：

> 请先介绍成员并讨论分工，暂时不要运行命令或修改文件。

第二台机器重复配对和本机授权步骤，就能加入同一项目。

## 以后怎么使用

| 操作 | 会发生什么 |
|---|---|
| 关闭应用窗口 | 接收服务继续运行，agent 继续工作 |
| 停止接收任务 | 当前调度轮次结束后停止；已有作业继续，结果重新连接后回传 |
| 重启电脑 | 打开应用，点“启动接收”；身份和会话保留 |
| 选择原数据文件夹 | 继续使用原机器身份、项目和记忆 |
| 换网络 | 能访问原服务地址即可，不需要重新配对 |

旧命令行执行端若仍在使用同一数据目录，应用会提示；应先停止旧执行端，不能同时运行两个接收器。不要删除原目录或用重新配对来绕过。

## 我们的 5090 与 4090

| 项目 | 5090 | 4090 |
|---|---|---|
| 应用中的服务地址 | `http://127.0.0.1:8765` | `http://127.0.0.1:18876`（依赖已有受保护转发） |
| 原本机数据目录 | `D:\tools\agent-harness-data\local5090` | `C:\Users\admin\AppData\Local\AgentHarness\lab4090` |

4090 的 18876 是设备通道，不是浏览器工作台地址；在 5090 使用共享面板，在 4090 可通过 Parsec 使用它自己的应用。其他团队需要运营者提供可达的 HTTPS 服务地址。应用里“创建工作台”只启动本机服务，不会自动开放公网端口。

开发与维护命令见 [运行说明](OPERATIONS.md)。
