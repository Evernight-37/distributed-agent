# Agent Harness

把不同电脑上的 agent 接入同一个项目工作群。人创建项目，管理员 agent 协调分工，每个人掌握自己机器的模型和执行权限。

**第一次使用：[图解新手教程](http://127.0.0.1:8765/guide) · [GitHub 上的逐步教程](docs/QUICKSTART.md)**

正式 Windows 应用已经按“本地账户 → 控制台 → 项目 → 设置”实现。设计稿保留用于对照，正式应用没有示例数据。

## 打开应用

解压应用包，双击 `AgentHarness.exe`，保留整个文件夹。无需安装 Python 或在终端输入命令；Windows 需要可用的 Edge WebView2 运行时。

**v5.1.1 修复：** 修复中文 Windows 用户名导致后台接收服务启动失败的问题。若 v5.1 在创建账户后提示“接收服务未启动”，解压新版完整文件夹，关闭旧窗口，打开新版并选择已有账户登录；不要重复注册或删除账户数据。应用版本共用原本的本机账户目录。

1. 首台电脑点 **创建账户**，填写名称和本地解锁密码。密码不限长度，可以留空。默认会使用本机协作服务。
2. 第二台电脑点 **加入已有账户**，填写同一协作服务的可达地址，得到关联码。
3. 回已有电脑的 **设置 → 账户与设备 → 输入新电脑的关联码**，核对名称与指纹，批准。第二台点击 **检查批准并完成关联**。
4. 控制台的 **我的 Agents → 添加员工** 可以选择任意自己的关联机器。员工初始未配置、未启用；在设置里明确选择该机器的目录、模型、思考强度和阶段。
5. 新建项目，进入后 **派遣我的员工**。群主设置管理员并邀请他人；其他人使用自己的账户凭项目邀请加入，再派遣自己的员工。

账户的私钥在本机加密保存，本地解锁密码不发给服务；每台机器有独立身份。共享服务保存账户公钥、项目、消息与员工摘要，不同步项目文件、模型凭据、环境或数据集。不同机器的本地密码可以不同。

远端机器在线并确认后，创建、设置、派遣才算生效；离线操作显示等待确认。撤回禁止后续任务，已经启动的后台作业继续独立运行。所有项目的人类成员能审阅项目中的群聊与私聊；agent 收到的上下文按频道过滤。

应用关闭后默认后台接收仍运行；可在设置改变这一偏好。重启电脑后打开应用登录，接收服务会启动。开机自动启动、账户备份和旧版账户自动迁移暂未提供，入口已禁用；原版工具、账户与工作目录继续保留。

## 在应用里配置团队入口

在托管协作服务的电脑登录应用，打开 **设置 → 协作服务 → 创建团队入口**。应用检查已安装并登录的 Tailscale，创建指向本机服务的私人 HTTPS 入口；如果需要首次授权，点 **打开 Tailscale 授权页面**，确认后回应用即可自动完成检查。

已经配置过的入口会直接显示，无需重新创建。可以 **复制地址**、**检测连接** 或 **停止团队入口**。检测验证当前账户能通过这个地址访问正确的服务；停止只移除本应用的入口，不删除项目或终止作业。已有其它 443 服务或 Funnel 配置会显示冲突，应用不会覆盖。

同事先获得 Tailscale 网络访问权限，再在“创建账户”的连接设置填写复制的地址，凭项目邀请加入。Tailscale 安装、登录与成员邀请仍由用户在 Tailscale 中完成。关闭应用窗口不会关闭已创建的入口；托管电脑和本机协作服务必须保持运行。

## 多人多机

同一项目的成员使用同一个协作服务。服务不赋予托管者应用内的项目群主权，但服务运营者能够读取数据库，成员需信任运营者。跨机器需要显式可达的 HTTPS 地址或已建立的本机网络转发；应用不会开放防火墙或安装组网软件。

本机账户数据在 `%LOCALAPPDATA%\AgentHarness\app-v5`，后台执行状态按设备分开。首次运行模型前，每台机器需要已有可用 Codex 登录。新界面不读取或传输 Codex、SSH 或 GitHub 凭据。

共享服务负责消息和任务队列，每台机器主动领取任务。后台命令必须经过本机主人批准。任何人都可以托管服务；合作伙伴加入同一个服务，不同服务暂不会自动同步。

代码与运行数据分开保存。不要提交设备令牌、认证文件或运行状态。当前面向小型可信团队，消息路由需要信任服务运营者。
