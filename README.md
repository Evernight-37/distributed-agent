# Agent Harness

把不同电脑上的 agent 接入同一个项目工作群。人创建项目，管理员 agent 协调分工，每个人掌握自己机器的模型和执行权限。

**第一次使用：[图解新手教程](http://127.0.0.1:8765/guide) · [GitHub 上的逐步教程](docs/QUICKSTART.md)**

正式 Windows 应用已经按“本地账户 → 控制台 → 项目 → 设置”实现。设计稿保留用于对照，正式应用没有示例数据。

## 打开应用

解压应用包，双击 `AgentHarness.exe`，保留整个文件夹。无需安装 Python 或在终端输入命令；Windows 需要可用的 Edge WebView2 运行时。

**v5.1.1 修复：** 修复中文 Windows 用户名导致后台接收服务启动失败的问题。若 v5.1 在创建账户后提示“接收服务未启动”，解压新版完整文件夹，关闭旧窗口，打开新版并选择已有账户登录；不要重复注册或删除账户数据。应用版本共用原本的本机账户目录。

**v5.2 生命周期修复：** 关闭窗口时明确选择后台运行或完全退出。后台程序装入本机应用数据目录；完全退出会验证本机服务已停止。旧版从解压目录运行的协作服务，可在新版点“完全退出”结束；若有独立作业仍在执行，需等待作业完成后才能删除旧目录。

**v5.2.1 登录修复：** 完全退出后，使用绑定本机默认协作服务的账户登录时，应用会先重新启动本机服务。连接失败提示会显示目标服务地址，方便分辨本机地址与团队地址。

**v5.3 跨团队身份：** 使用原有本机身份加入其他服务托管的项目，控制台汇总项目；首个服务暂时离线时，仍可查看其他可达服务上的项目。

**v5.4 模型请求代理：** 在应用 **设置 → 模型请求代理** 为当前电脑开启或关闭本机代理，并填写端口。地址固定为 `127.0.0.1`，只影响这台电脑之后启动的 Codex 任务；团队服务和 Tailscale 不受影响。每台电脑分别设置，已有任务继续使用启动时的网络环境。

**v5.5 群聊与 Codex 检测：** 设置页可检测本机 Codex CLI，并在自动检测失败时选择 `codex.exe` 或 `codex.cmd`；后台接收端同时检查桌面安装目录、npm 目录及 PATH。群聊不再发布 `[CHECKPOINT]` 过程标记，项目页和后台队列缩短轮询间隔。模型自身的生成时间仍取决于所选模型、思考强度和任务内容。

**v5.6 保活、流式群聊与点名：** 本机项目收到任务时启动 Codex App Server，连续消息复用同一进程；无活动后按 **设置 → Agent 空闲保活** 的时间退出，默认 5 分钟。公开回复逐步显示，新的人类消息排在正在回复的气泡下方并留到下一轮。群聊可用“呼叫 Agent”选择特定员工；未点名的公开消息仍由管理员处理。Agent 可以返回空回复，任务列表会显示“已处理 · 未发言”。项目页刷新会保留聊天和页面滚动位置、任务折叠状态，历史消息明确显示发送者。流式草稿只来自结构化结果的 `reply` 字段；私聊和任务指令不作为公开增量传输。

**v5.7 聊天修复：** Enter 发送、Shift+Enter 换行，中文输入法组合期间不会误发送；消息文本可选择复制。设置页不再反复重建 Codex CLI 卡片，首次扫描路径会写入本机配置，“重新检测”才再次扫描。发送消息前检查团队服务是否支持点名和回复占位，避免新版窗口连接旧服务时误把点名发给管理员；托管团队服务的电脑更新后须重启该服务。

**v5.7.1 自动协作额度：** 项目页显示剩余轮次，群主可恢复额度。最后一轮优先处理明确点名或私聊的消息；额度耗尽时调度器不再把同一批任务回滚。项目成员和任务会显示目标机器离线，任务列表也会提示找不到 Codex CLI 的失败；机器主人需在本机设置页确认任务接收及可用程序。

**v5.8 按需停机：** 移除项目自动协作轮次限制与额度按钮；旧数据库中的额度数值不再参与调度。新的人类消息会唤醒相应 Agent，同一 Agent 同时只处理一轮。Agent 可以返回空回复且不派新任务；没有新消息或待执行工作时不再发起模型调用，保活进程在设定的空闲时间后退出。机器离线、模型失败或超时仍需机器主人处理，不会因为移除额度而自动无限重试失败任务。

**v5.9 项目会话与共享记忆：** 项目页按大群、人和 Agent 私聊、人和人私聊、Agent 内部对话分开显示。人参与的私聊只对会话参与者可见；Agent 间内部对话对项目中的人可见，默认折叠。群聊未点名时唤醒管理员 Agent；点名其他 Agent 时只唤醒被点名者。项目记忆保存在协作服务，项目成员可添加条目；Agent 只可从公开群聊提炼共享记忆，私聊不会自动写入。新版客户端会要求服务端声明 `conversation_privacy_v2`，旧服务需升级并重启后才能在新版中读取项目聊天。

**v5.9.1 任务状态修复：** Codex CLI 在 WebSocket 超时后可能提示切换至 HTTPS，并继续完成任务。若最终退出码为 0、收到 `turn.completed` 且返回报告，Harness 现在会进入待审阅状态；真正的执行失败、无报告、取消、超时和模型不匹配仍按原规则处理。此修复需要更新运行 Agent 的那台机器上的客户端。

**v5.10 服务托管归属：** 新建项目只能选择当前账户名下的协作服务；加入别人的项目不会授予使用对方机器托管新项目的权限。项目群主与服务托管者仍是不同身份，现有项目及成员保持不变。v5.10 当时提供的“启用本机托管”和目录选择操作已在 v5.12 移除。

**v5.11 界面与登录修复：** 左侧改为控制台、设置、账户三个图标；控制台集中显示项目与 Agents。进入项目后只显示会话列表与聊天区，任务、记忆及成员工具折叠在聊天区下方。账户图标管理关联设备和退出。Windows 下的账户文件权限命令改为无窗口执行，避免登录时短暂闪出终端。

**v5.12 本机托管简化：** 设置页不再要求启用服务或选择数据目录。在控制台新建项目时选择“这台机器”，应用会按需启动本机协作服务；新安装的数据自动放在 `AgentHarness.exe` 所在文件夹的 `data` 中。升级时保留整个应用文件夹及 `data`，不要只替换 exe 或删除旧数据。正在使用旧目录的服务会先核对服务身份并继续沿用旧数据，不会把已有项目切换到空目录。

**v5.12.1 私聊与项目面板修复：** 人只能与自己拥有的 Agent 建立私聊，界面和服务端同时校验；项目里的其他 Agent 仍可在群聊中被点名。项目自动刷新会保留任务与执行、项目记忆、成员与员工三个面板的展开状态及内部滚动位置。

**跨团队身份：** 一个人只创建一次身份。加入其他团队时，在自己的控制台点“凭邀请加入项目”，填写对方的协作服务地址和项目邀请代码。应用使用现有身份签名证明成员身份；新服务会登记公钥及项目成员权限，但无需重新创建本地账户。控制台汇总已加入服务上的项目；同一身份的其他关联设备也能看到这些项目。

1. 首台电脑点 **创建账户**，填写名称和本地解锁密码。密码不限长度，可以留空。默认会使用本机协作服务。
2. 自己的第二台电脑点 **关联我的另一台电脑**，填写首个协作服务的可达地址，得到关联码。
3. 回已有电脑的 **设置 → 身份与关联设备 → 输入新电脑的关联码**，核对名称与指纹，批准。第二台点击 **检查批准并完成关联**。
4. 控制台的 **我的 Agents → 添加员工** 可以选择任意自己的关联机器。员工初始未配置、未启用；在设置里明确选择该机器的目录、模型、思考强度和阶段。
5. 新建项目，进入后 **派遣我的员工**。群主设置管理员并邀请他人；其他人使用自己的现有身份，在控制台凭服务地址和项目邀请代码加入，再按需接入机器、派遣自己的员工。

账户的私钥在本机加密保存，本地解锁密码不发给服务；每台机器有独立身份。共享服务保存账户公钥、项目、消息与员工摘要，不同步项目文件、模型凭据、环境或数据集。不同机器的本地密码可以不同。

远端机器在线并确认后，创建、设置、派遣才算生效；离线操作显示等待确认。撤回禁止后续任务，已经启动的后台作业继续独立运行。项目人类成员都能查看群聊和 Agent 间内部对话；人参与的私聊仅参与者可见。Agent 收到的上下文按会话过滤，项目记忆由项目成员共享。

关闭窗口时应用会让你选择“继续后台运行”或“完全退出”。完全退出会等待本机接收端和由本应用启动的协作服务停止；已启动的独立作业会继续运行。后台程序使用 `%LOCALAPPDATA%\AgentHarness\service-runtime` 中按版本保存的运行文件，因此关闭便携应用窗口后，解压目录可以删除。重启电脑后打开应用登录，接收服务会启动。开机自动启动、账户备份和旧版账户自动迁移暂未提供；账户与工作目录继续保留。

## 在应用里配置团队入口

在托管协作服务的电脑登录应用，打开 **设置 → 协作服务 → 创建团队入口**。应用检查已安装并登录的 Tailscale，创建指向本机服务的私人 HTTPS 入口；如果需要首次授权，点 **打开 Tailscale 授权页面**，确认后回应用即可自动完成检查。

已经配置过的入口会直接显示，无需重新创建。可以 **复制地址**、**检测连接** 或 **停止团队入口**。检测验证当前账户能通过这个地址访问正确的服务；停止只移除本应用的入口，不删除项目或终止作业。已有其它 443 服务或 Funnel 配置会显示冲突，应用不会覆盖。

同事先获得 Tailscale 网络访问权限，再使用自己已有身份，在控制台“凭邀请加入项目”填写这个地址和项目邀请代码。只有第一次使用应用的人需要创建自己的身份；不用为每个团队另建账户。Tailscale 安装、登录与成员邀请仍由用户在 Tailscale 中完成。关闭应用窗口不会关闭已创建的入口；托管电脑和本机协作服务必须保持运行。

接受 Tailscale 用户邀请后，还需在同事电脑上的 Tailscale 客户端登录并切换到受邀网络，让设备出现在该网络的 Machines 列表；如启用了设备批准，还要批准这台设备。桌面应用加入项目时会连接团队 HTTPS 地址。当前旧版网页工作台会拒绝直接在浏览器打开该 HTTPS 地址的首页，浏览器报错不能单独说明设备间不通。

## 多人多机

同一项目的成员连接该项目所在的协作服务。同一个身份可以参加多个服务上的项目；各服务只保存自己托管的项目。服务不赋予托管者应用内的项目群主权，但服务运营者能够读取其数据库，成员需信任运营者。跨机器需要显式可达的 HTTPS 地址或已建立的本机网络转发；应用不会开放防火墙或安装组网软件。

设备撤销目前在执行操作的协作服务内生效，不会自动撤销其他服务中同一设备的权限。每个服务的负责人应分别处理遗失设备；跨服务统一撤销尚未提供。

本机账户数据在 `%LOCALAPPDATA%\AgentHarness\app-v5`，后台执行状态按设备分开。首次运行模型前，每台机器需要已有可用 Codex 登录。新界面不读取或传输 Codex、SSH 或 GitHub 凭据。

各项目所在的服务负责该项目的消息和任务队列，每台机器主动领取任务。后台命令必须经过本机主人批准。任何人都可以托管服务；同一身份能加入多个服务，不同服务的项目内容不会互相复制。

代码与运行数据分开保存。不要提交设备令牌、认证文件或运行状态。当前面向小型可信团队，消息路由需要信任服务运营者。
